# «Советский пластик» (КарболитЪ) — перенос из Claude Design

Сайт коллекции карболитовых статуэток и админ-панель. Проект перенесён из Claude Design
(формат Design Components, файлы `*.dc.html`) на **React 18 + TypeScript + Vite 6**.
Цель переноса — повторить страницы, тексты, внешний вид и поведение оригинала без переработки.

- Исходные файлы из Claude Design лежат без изменений в `original-export/` (см. `original-export/README.md`).
- Перенесённая версия — в `src/`.
- Документация: `ROUTES.md`, `FUNCTIONALITY.md`, `DESIGN-TOKENS.md`, `HANDOFF.md`.
- Эталонные скриншоты перенесённой версии: `docs/screenshots/` (с отчётом проверки `report.json`).
- Что и как проверено: `docs/VERIFICATION.md`.

## Требования

- Node.js **20.19 или новее** (проверено на Node 22.23.4, npm 10.9.9).
- npm (lock-файл `package-lock.json` создан npm).
- Современный браузер. Для скрипта скриншотов — Python 3 и пакет `playwright` (необязательно).

## Установка и запуск

```bash
npm ci            # установка зависимостей строго по package-lock.json
npm run dev       # сервер разработки: http://localhost:5173

Другие команды:

```

## Структура проекта

Архив SkillSwap использован как пример организации; исходники этого сайта находятся в `src`.

```text
src/
  app/                    # App.tsx, App.ts, App.css
  components/
    SiteHeader/           # SiteHeader.tsx, SiteHeader.ts, SiteHeader.css
    SiteFooter/           # SiteFooter.tsx, SiteFooter.ts, SiteFooter.css
  pages/
    Main/                 # Main.tsx, Main.ts, Main.css
    Catalog/              # тот же принцип для каждой страницы
    Admin/
      Admin.tsx
      Admin.ts
      Admin.css
      sections/           # отдельная папка с тройкой файлов на каждую секцию
    NotFound/             # страница 404
  features/               # общая логика избранного и админ-панели
  data/                   # модели, чтение и демонстрационные данные
  runtime/                # адаптер исходных Design Components
  main.tsx                # запуск React и подключение шрифтов
  routes.ts               # адреса страниц
public/
  images/                 # логотипы и изображения; доступны по /images/...
    figures/              # предоставленные SVG статуэток
```

У каждого элемента интерфейса три файла: `.tsx` — разметка и подключение,
`.ts` — логика или типы входных данных, `.css` — стили. Импорты элементов
явно указывают `.tsx`, поскольку рядом находится одноимённый `.ts`.
Секции админ-панели используют общие стили `Admin.css`; их собственные CSS подготовлены
для индивидуальных правил. Служебным модулям без интерфейса CSS не требуется.

`public` содержит статические ресурсы, `src` — исполняемый код. Исходный экспорт
сохранён в `original-export`, документация — в `docs`. Сервер авторизации находится в `wserver`; существующие демонстрационные данные и localStorage сохранены.

Старый `scripts/convert-dc.mjs` относится к первоначальному экспорту и создаёт прежнюю
структуру из четырёх файлов. Команда `npm run convert` удалена, чтобы случайная
перегенерация не отменила новую организацию проекта.

### Варианты из панели Tweaks

В Claude Design у некоторых страниц были настройки (Tweaks). Здесь они задаются параметрами адреса:

| Адрес | Что меняет |
|---|---|
| `/?newsMode=show` / `hide` / `auto` | Карусель новостей на главной: всегда / никогда / только если новости свежее 90 дней (по умолчанию `auto`) |
| `/login?mode=register` | Открыть сразу вкладку «Регистрация» (по умолчанию `login`) |
| `/admin?canvasPreview=false` | Отключить демонстрационный просмотр админки без входа (по умолчанию `true`, как в оригинале) |
| `/account?signedIn=false` | Как выглядит кабинет без входа. По умолчанию `true`, как в оригинале: если в браузере нет отметки входа (`sp-auth`), кабинет показывается в демонстрационном «вошедшем» виде |
| `/account?editOpen=true` | Сразу открыть окно «Редактировать профиль» (по умолчанию `false`) |
| `/_design/site-header?current=catalog&signedIn=true` | Варианты шапки |

## Демонстрационный режим

Сервера и базы данных нет — ни в оригинале, ни здесь. Всё работает в браузере:

- **Данные** хранятся в `localStorage` браузера (ключ `sp-db` и другие, см. `HANDOFF.md`).
  Они видны только в этом браузере на этом компьютере. Очистить: DevTools → Application → Local Storage → удалить ключи `sp-*`.
- При первом открытии админки или страницы входа создаётся демонстрационная база: 24 статуэтки-заглушки,
  6 типов, 10 меток, 3 автора, 5 статей, 2 пользователя.
- **Демо-доступ администратора:** почта `admin@karbolit.ru`, пароль `karbolit`.
  Второй демо-пользователь: `anna@example.ru` / `anna123` (без прав администратора).
  Это демонстрационные значения из исходного проекта, а не настоящие учётные данные.
- «Вход» — проверка по демо-базе в браузере. Пароли хранятся простым хешем (не криптографическим) —
  это не защита, а имитация для показа.
- Админка по умолчанию (`canvasPreview=true`, как в оригинале) открывается в режиме просмотра даже без входа.
  Чтобы проверить настоящее разграничение доступа, откройте `/admin?canvasPreview=false`.

Переменные окружения не нужны (`.env.example` поэтому нет).

## Известные ограничения

- Нет сервера: данные не общие для разных пользователей и устройств, фото хранятся в `localStorage`
  (лимит браузера — обычно около 5 МБ). Список действий, которым нужен сервер, — в `FUNCTIONALITY.md`.
- Картинки статуэток — заглушки-силуэты из оригинала. Настоящих фотографий в проекте не было.
- Страница статуэтки и статья открываются без идентификатора в адресе (`/figurine`, `/article`):
  выбранная статуэтка, как и в оригинале, передаётся через `localStorage` (`sp-item`).
- Визуальное сравнение со средой Claude Design в этой сессии выполнить не удалось
  (нет доступа к её рендереру) — см. раздел «Что проверено» в `HANDOFF.md`.
- Код логики перенесён без изменения поведения и помечен `// @ts-nocheck`: типы для него ещё не написаны.

## Вход, регистрация и почта Яндекса

В двух терминалах из папки проекта:

```powershell
npm.cmd run server
```

```powershell
npm.cmd run dev
```

Откройте http://localhost:5173/login. Старые демонстрационные аккаунты localStorage
не переносятся в серверную базу: зарегистрируйте аккаунт заново.
Пользователи сохраняются в `wserver/data/users.json`, пароли — как scrypt-хеши с солью.
Сессии и одноразовые коды хранятся в памяти: после перезапуска сервера войдите заново.
Данные коллекции пока остаются в браузере, сервер авторизации их не синхронизирует.

Для отправки писем заполните `wserver/.env`:
- `SMTP_USER` — ящик Яндекса;
- `SMTP_FROM` — тот же ящик;
- `SMTP_PASS` — пароль приложения для Почты, созданный в Яндекс ID.

SMTP: `smtp.yandex.ru`, SSL, порт 465. Разрешите доступ почтовых клиентов в настройках
Яндекс Почты. Инструкция: https://www.yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others
После изменения `.env` перезапустите сервер. Секреты не копируйте в `src` или `public`.
Без настроенной почты вход и регистрация работают, восстановление сообщает о необходимости настройки.
Доставка реальных писем требует проверки с вашим ящиком; автотест подменяет отправку письма.

Проверка API: `npm.cmd run test:auth`. Сборка: `npm.cmd run build`.
Для публикации нужно проксировать `/api` на сервер авторизации и использовать HTTPS
с `COOKIE_SECURE=true` и `APP_ORIGIN`, равным адресу сайта. Текущий сервер предназначен
для локальной разработки; JSON-хранилище рассчитано на один процесс.

## Композиция компонентов

Каждый элемент интерфейса имеет свою папку с тремя файлами: `Name.tsx`
(разметка и импорт CSS), `Name.ts` (типы входных данных и логика), `Name.css` (стили).

```text
src/components/
  ui/
    Button/                  # базовая кнопка
    CollectionActionButton/  # общая форма кнопок отметок
    LikeButton/              # сердце «Хочу купить»
    CheckButton/             # галочка «Есть в коллекции»
    CloseButton/             # закрытие окна
    TextInput/
    Checkbox/
    TextArea/
    Select/
    Link/
  cards/
    FigureCard/              # карточка, собирающая кнопки и поля
    PurchasePlanFields/      # поля магазина и примерной цены
  modals/
    Modal/                   # контейнер, фон и кнопка закрытия
    AuthRequiredModal/       # окно входа
    PurchasePlanModal/       # окно плана покупки
  SiteHeader/                # композиция меню, ссылок и кнопок
  SiteFooter/
```

Страницы импортируют `FigureCard`, которая импортирует `LikeButton`, `CheckButton`
и `PurchasePlanFields`; последние используют базовые элементы из `ui`.
Один компонент карточки используется в Main, Catalog, Figurine и Account.
Состояние коллекции и обработчики сохраняются в логике страниц и передаются через props:
кнопки не создают собственную копию состояния избранного.
Компоненты импортируются явно: `.../LikeButton/LikeButton.tsx`.
Общие стили элементов находятся рядом с ними; в CSS страниц остаются сетки,
оформление секций и индивидуальные варианты элементов.

Проверка композиции компонентов и структуры папок: `npm.cmd run test:components`.
