### Как перенесён формат Claude Design

Страница в Claude Design — один файл: разметка с подстановками `{{ … }}`, блоки `<sc-if>` / `<sc-for>`,
стили в `<helmet>` и класс `Component extends DCLogic` с методом `renderVals()`. Перенос сделан так, чтобы
ничего не переписывать «по памяти»:

- Разметка преобразована в JSX механически: `{{ a.b }}` → `$v?.a?.b`, `<sc-if>` → условие, `<sc-for>` → `map`,
  `class` → `className`, строковые inline-стили → объекты стилей. Стили с `!important` записываются в атрибут как есть
  (`__raw`), потому что объекты стилей React не поддерживают `!important`. Пробелы между строчными элементами сохранены.
- Класс логики перенесён дословно. Отличия: общие методы вынесены в `features/wishlist`, чтение и заполнение
  демо-данных — в `src/data`, адреса `*.dc.html` и `/_blob/…` заменены на маршруты и `/images/…`.
- Стили страницы подключаются только пока страница на экране — у каждой страницы оригинала был свой документ,
  и, например, `body{background}` одной страницы не должен действовать на другую.
- Ссылки — обычные `<a href>` с полной загрузкой страницы, как переход между артбордами.

## Где что менять

- **Тексты и разметка страницы** — `src/pages/<Страница>/<Страница>.view.tsx` (для админки — `sections/*.tsx`).
- **Поведение, состояние, обработчики, данные для разметки** — `<Страница>.logic.ts`, метод `renderVals()` и методы класса.
- **Стили** — `<Страница>.css` (классы) и inline-стили в разметке. Значения — в `DESIGN-TOKENS.md`.
- **Шапка и подвал** — `src/components/SiteHeader`, `src/components/SiteFooter`.
- **Новый маршрут** — `src/routes.ts` и `src/App.tsx`.
- **Демонстрационные данные** — `src/data/demoDb.ts` (база админки), `src/data/demo/*.ts` (запасные карточки).
  Ещё часть фиксированного содержимого записана прямо в логике страниц как в оригинале: новости и карточки
  «Новости и статьи» на главной (`Main.logic.ts`, `renderVals`), заглушки статей (`Materials.logic.ts`),
  ракурсы статуэтки (`Figurine.logic.ts`), демонстрационные отметки кабинета (`Account.logic.ts`, `spLoad`).

## Данные и будущий API

Сейчас всё хранится в `localStorage` браузера:

| Ключ | Содержимое | Кто пишет |
|---|---|---|
| `sp-db` | демо-база: `{v:2, figures, photos, figureTags, infos, kinds, authors, tags, users, userNotes}` (или старая v1) | админка, вход/регистрация |
| `sp-auth` | `"1"` — отметка входа | вход, выход |
| `sp-profile` | профиль: email, имя, логин, валюта, аватар | вход, кабинет |
| `sp-want` | «Хочу купить»: id → `{note, price}` | карточки, кабинет |
| `sp-have` | «Есть в коллекции»: id → `true` | карточки, кабинет |
| `sp-item` | id статуэтки для страницы `/figurine` | переход с карточки |
| `sp-tag` | тег для фильтра каталога | переход с тега |
| `sp-admin` | id пользователя-администратора в сессии админки | кабинет («Админ-панель»), админка |

Схема `sp-db` v2 повторяет сущности из спецификации админки: Figure, Photo, FigureTag, Info, Kind, Author, Tag,
User, UserNote — с полями `createDate / createdBy / modifyDate / modifiedBy`. Неизвестные размеры и цены — `null`.

Как подключать API, не переделывая страницы:

1. Сделать серверное API (например, REST): `GET /api/figures`, `GET /api/figures/:id`, `GET /api/infos`,
   `POST /api/auth/login`, `POST /api/auth/register`, `GET/PUT /api/me`, `GET/PUT /api/me/wishlist`, и для админки
   CRUD на каждую сущность (`/api/admin/figures`, `/photos`, `/figure-tags`, `/infos`, `/kinds`, `/authors`, `/tags`,
   `/users`, `/user-notes`), загрузку фото (`POST /api/admin/photos`, multipart), экспорт (`GET /api/admin/<раздел>.csv`).
2. Публичные страницы читают данные только через `src/data/figuresFromDb.ts` и `src/data/articlesFromDb.ts` —
   заменить их на запросы к API. Сейчас эти функции синхронные: при переходе на API данные нужно загрузить в
   `componentDidMount` и положить в `state`, а `spItems()` / `spArticles()` — читать из `state`.
3. Админка работает с одной копией базы в `state.db` и сохраняет её целиком через `persist()` (`logic/helpers.ts`),
   а читает через `spReadDb()` → `readDemoDb()`. Для API: в `saveForm()`, `saveModal()`, `delRecord()`,
   `toggleVisible()`, работе с фото (`logic/actions.ts`) заменить изменение `db` + `persist()` на запрос к API и
   обновить `state.db` ответом сервера. Проверки ввода в браузере можно оставить, но сервер должен их повторять.
4. Вход: заменить проверку по `sp-db` в `Login.logic.ts` и `boot()` админки на ответ сервера; `sp-auth` и
   `sp-admin` — на серверную сессию (cookie `HttpOnly`). Права администратора проверять **на сервере** при каждом
   запросе к `/api/admin/*`.
5. **Не подключать браузер напрямую к SQL Server** и не класть в frontend учётные данные базы. База данных —
   только за серверным API. В `.env` frontend допустим разве что адрес API (`VITE_API_URL`), без секретов.

## Что важно сохранить

- Изоляцию стилей страниц (`definePage`) — пока стили не переписаны на модули.
- Правило «неизвестно ≠ 0» для размеров и цен; пароли нигде не показываются и не выгружаются.
- Админка открывается только пользователю с `isAdmin`; вход в неё — из личного кабинета; отдельной страницы входа в админку нет.
- Без входа отметки «Хочу купить» / «Есть в коллекции» не показываются, нажатие — окно «Войдите в аккаунт».
- Сущности и названия полей спецификации (Figure, Photo, … `OriginalID`, `final`, `Enable`, `Comment1–3`) —
  смысл части полей не определён, их не следует «додумывать».
- Без `React.StrictMode` (см. `src/main.tsx`): логика подписывается на события окна без отписки, как в оригинале.

## Что не удалось перенести и почему

- **Среда Claude Design** (`support.js`, `artifact-type/dc-runtime.js`, редактор, холст, панель Tweaks, комментарии) —
  это внутренние файлы типа артефакта, их сервер не отдаёт для копирования. Вместо них написан `src/runtime`
  (заменитель, а не оригинальная реализация). Расположение артбордов на холсте сохранено только как
  `original-export/project/canvas.json`.
- **Google Fonts** — вместо ссылки на fonts.googleapis.com шрифт Onest подключён локально из npm-пакета
  `@fontsource/onest` (пакет собран из файлов Google Fonts; их версия может немного отличаться от той, что отдаёт Google сейчас).
- **Изображение `c53ab0a407170dcfa36db989bf7b0144` (PNG)** в хранилище артефакта не используется текущими страницами и
  недоступно для чтения — не включено.
- **Визуальное сравнение с оригиналом** в среде Claude Design не выполнено: в этой сессии нет доступа к её рендереру.
  Перенос механический (разметка и стили — те же), но мелкие отличия возможны там, где среда Claude Design сама
  добавляла стили или по-своему обрабатывала разметку. Это нужно проверить глазами по `docs/screenshots`.

## Особенности оригинала, сохранённые как есть

- Админка на ширине ≤ 800 px: строки «Последние изменения» на обзоре шире экрана (правило `min-width: 860px`
  для `.a-tr`), из-за этого появляется горизонтальная прокрутка страницы. Стили те же, что в оригинале.
- Окно «все теги» на странице статуэтки есть, но кнопки, которая его открывает, нет.
- Вход с почтой, которой нет в демо-базе, проходит с любым паролем.
- Кабинет по умолчанию показывается «вошедшим» (настройка `signedIn=true`); админка по умолчанию открывается в
  демо-просмотре (`canvasPreview=true`).
